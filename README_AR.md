# نظام تدريب الامتياز — حزمة النشر على Netlify (نموذج تجريبي)

كلية الطب – جامعة جازان. مالك المنصة: طارق عبده حسن طاهري.

## ما في الحزمة
| الملف | الوظيفة |
|---|---|
| `public/index.html` | الصفحة الكاملة (واجهة عربية RTL) مع طبقة التوافق. |
| `netlify/functions/api.mjs` + `lib.mjs` | الخادم: الدخول بجلسة، وقاعدة بيانات مشتركة (Netlify Blobs)، وقفل الحساب، وصلاحيات الأدوار، وقراءة نموذج التقييم. |
| `netlify.toml`, `package.json` | إعداد النشر. |
| `.env.example` | المتغيرات المطلوبة. |
| `students_template.xlsx` | قالب استيراد الطلاب. |
| `serve_local.mjs` | تشغيل محلي للاختبار فقط (`node serve_local.mjs` ثم http://localhost:8766). |

## خطوات النشر (الطريقة المضمونة: Git أو سطر الأوامر)
> السحب والإفلات (Netlify Drop) يرفع الصفحة فقط ولا يضمن بناء الدوال وتثبيت اعتماداتها، فلا تعتمد عليه.

**الخيار أ — GitHub (الأسهل للتحديثات):**
1. أنشئ مستودعًا خاصًا (Private) وارفع محتويات هذا المجلد كما هي.
2. في Netlify: Add new site ← Import an existing project ← اختر المستودع. لا تغيّر الإعدادات (يقرؤها من `netlify.toml`).

**الخيار ب — سطر الأوامر:**
```
npm i -g netlify-cli
npm install
netlify login
netlify init        # أو netlify link لموقع قائم
netlify deploy --prod
```

## المتغيرات (Site configuration ← Environment variables)
| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `OWNER_PASSWORD` | نعم | كلمة سر مالك المنصة. القيمة المعتمدة موجودة في `.env.example`. أدخلها في Netlify ولا تضعها في الشيفرة. بدونها لا يعمل دخول المالك. |
| `SESSION_SECRET` | موصى به | نص عشوائي طويل لتوقيع الجلسات. |
| `ANTHROPIC_API_KEY` | اختياري | لتفعيل قراءة نموذج التقييم الممسوح ضوئيًا. بدونه يُخفى الرفع التلقائي ويُدخل المشرف التقييم يدويًا. |
| `ANTHROPIC_MODEL` | اختياري | الافتراضي `claude-sonnet-5-5`. |

بعد إضافة المتغيرات نفّذ **Trigger deploy** من جديد.

## أول تشغيل (قبل الإطلاق)
1. افتح الموقع ← تبويب «مالك المنصة» ← أدخل `OWNER_PASSWORD`.
2. **الإعدادات:** راجع فصول التخرج والفترات وفتح الحجز، وعقد الإقرار، وغرفة الانتظار (الحجم والمدة).
3. **القاعدة الرئيسية ← وحدة الامتياز:** بريد الوحدة وهاتفها. **المستشفيات:** البريد الإلكتروني لإدارة التدريب في كل مستشفى.
4. **القاعدة الرئيسية ← المنسوبون:** أضف المنسقين والمشرفين (اسم مستخدم + السجل المدني ككلمة سر).
5. **القاعدة الرئيسية ← الطلاب ← استيراد:** ارفع ملف `students_template.xlsx` بعد تعبئته.
6. جرّب بحساب طالب ومشرف، ثم من شاشة المالك استخدم **تفريغ البيانات** لمسح بيانات التجربة (الحجوزات والطلبات) مع إبقاء الطلاب إن رغبت.
7. شارك رابط الموقع.

## حدود النموذج التجريبي (يجب معرفتها قبل التشغيل الحقيقي)
- كلمة سر الطالب والموظف هي **السجل المدني** (محفوظ بنص واضح في القاعدة). الحل في النظام الفعلي: دخول موحد (نفاذ / SSO) أو كلمات سر مجزّأة.
- الصلاحيات على الخادم مبسطة (الطالب لا يقرأ بيانات غيره ولا يكتب في الإعدادات)، لكنها ليست تدقيقًا كاملًا لكل حقل. الدرجات المعتمدة تُقفل بالواجهة لا بالخادم.
- القاعدة (Netlify Blobs) تناسب تجربة مغلقة (عشرات المستخدمين). لحمل مئات الطلاب في وقت واحد يلزم قاعدة علائقية (Postgres) بمعاملات.
- قفل الحساب: 5 محاولات خاطئة ← 15 دقيقة. الجلسة 12 ساعة.
- لا توجد نسخ احتياطية تلقائية: صدّر بيانات الطلاب والتسجيلات (Excel) دوريًا من النظام.

## الحسابات وكلمات المرور
- من «القاعدة الرئيسية ← الحسابات» يرى المالك اسم كل مستخدم وكلمته الأولية، ويولّدها أو يعيّنها يدويًا، ويصدّرها إلى Excel لتسليمها.
- عند أول دخول تظهر صفحة تغيير كلمة المرور إلزاميًا، ويفرضها الخادم أيضًا. بعد التغيير تُحفظ الكلمة مشفّرة ولا تظهر لأحد.
- لا تضع كلمة سر المالك داخل أي ملف في الحزمة: يفشل نشر Netlify إن وجد قيمة متغير سرّي داخل الملفات.

## النسخ الاحتياطي إلى OneDrive (اختياري)
نسخة كاملة (البيانات + المرفقات) مضغوطة `imt-backup-<تاريخ>.json.gz` تُرفع **تلقائيًا كل يوم 4 صباحًا بتوقيت الرياض**، ويمكن للمالك طلب نسخة فورية من **الإعدادات ← النسخ الاحتياطي إلى OneDrive**. يُحتفظ بآخر 30 نسخة (قابل للتغيير).

**الإعداد في Microsoft Entra (يقوم به مسؤول Microsoft 365):**
1. Entra ID ← App registrations ← New registration (اسم مثل `IMT Backup`).
2. API permissions ← Microsoft Graph ← **Application permissions** ← `Files.ReadWrite.All` ← **Grant admin consent**. (لتقييدها على مجلد واحد استخدم `Sites.Selected` أو اطلب من المسؤول سياسة وصول للتطبيق.)
3. Certificates & secrets ← New client secret، وانسخ **قيمته** فورًا.
4. دوّن: `Directory (tenant) ID` و`Application (client) ID`.

**المتغيرات في Netlify:**
| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `MS_TENANT_ID` | نعم | Directory (tenant) ID |
| `MS_CLIENT_ID` | نعم | Application (client) ID |
| `MS_CLIENT_SECRET` | نعم | قيمة السر (لا تضعه في الشيفرة أو المحادثات) |
| `MS_DRIVE_USER` | نعم* | البريد الجامعي لصاحب OneDrive الذي ستُحفظ فيه النسخ (أو استخدم `MS_DRIVE_ID` لمكتبة محددة) |
| `MS_FOLDER` | لا | اسم المجلد، الافتراضي `IMT-Backups` (يُنشأ تلقائيًا) |
| `BACKUP_KEEP` | لا | عدد النسخ المحفوظة، الافتراضي 30 |

بعد الإضافة نفّذ **Trigger deploy**. ثم من الإعدادات اضغط «نسخ احتياطي الآن» وراجع الحالة.

**الاستعادة:** من جهازك بعد تنزيل الملف من OneDrive: `npm install` ثم
`NETLIFY_SITE_ID=... NETLIFY_TOKEN=... node restore_backup.mjs الملف.json.gz` (تشغيل تجريبي)، وأضف `--yes` للكتابة الفعلية. جرّب الاستعادة على موقع اختبار قبل الاعتماد عليها.

**تنبيهات:** الملف يحوي كلمات السر الأولية للطلاب (نموذج تجريبي) فاحصر الوصول للمجلد. الدوال المجدولة والخلفية تعمل عند النشر عبر Git أو سطر الأوامر، وقد لا تُفعَّل عند الرفع بالسحب والإفلات؛ تأكد من ظهور `backup-scheduled` في Functions بعد النشر.
